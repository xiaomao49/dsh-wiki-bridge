# 归档约定（Vault 维护规范）

> WikiBridge 插件的知识库工作流约定：沉淀、归档、体检、遗忘四阶段都遵守本文件。
> 复制本文件到你的 Obsidian vault 根目录（命名为 `_约定.md`）即可启用。

## 目录结构

| 路径 | 用途 |
|------|------|
| `收件箱/` | **新笔记/素材入口**——随手丢这里，定期统一处理 |
| `归档/` | **遗忘区**——过时/废弃知识存放，不参与检索与自动注入 |
| `Caelestia/` `系统维护/` `网络/` `应用/` `服务/` `开发/` | 知识分类目录 |
| `首页.md` | 总索引——**新页面必须登记** |

> 分类目录与插件 `lib/index.js` 的 `CATEGORIES` 白名单一一对应；调整分类时需同步修改插件代码。

## 页面规范

- 文件名：中文短名，不用空格和特殊符号
- 每页开头 frontmatter：

  ```yaml
  ---
  title: 页面标题
  created: YYYY-MM-DD
  updated: YYYY-MM-DD
  tags: [分类标签]
  ---
  ```

- **标签白名单**（新增标签必须先加进本表）：

  `caelestia` · `hyprland` · `系统` · `网络` · `字体` · `终端` · `编辑器` · `微信` · `排障` · `配置` · `流程` · `代理` · `docker` · `开发`

  > 与插件 `lib/index.js` 的 `TAG_WHITELIST` 对应；新增标签需同步修改插件代码。

- 每页至少 **2 个 `[[双链]]`**
- 页面超 200 行要拆分

## 知识生命周期（插件工作流）

1. **沉淀**：说"记一下" → `wiki_write` 写入 `收件箱/`（自动 frontmatter + 凭据脱敏 + 标签白名单校验 + 查重）
2. **归档**：说"做周维护" → `wiki_archive` 移入分类目录 + 刷新 frontmatter + 自动登记首页
3. **体检**：说"体检一下" → `wiki_check` 按本规范检查（断链 / frontmatter / 双链 / 首页登记 / 标签白名单 / 行数 / 过时）
4. **遗忘**：`updated` 超过阈值（默认 90 天，设置页可调）未更新 → 体检报告"可能过时" → 人工裁决移入 `归档/`

## 会话 → wiki 提炼标准

- **值得记**：修复方案、配置变更、决策理由、踩坑教训、官方文档结论
- **不值得记**：纯对话、临时状态、已被替代的内容、琐碎操作
- **去重**：已有页面 → 追加更新 + 改 `updated` 日期；禁止创建重复页

## 铁律

- 不重构现有目录结构
- 不修改 `收件箱/` 之外的文件内容（除非是维护任务）
- 会话原文不是权威，只有提炼后的知识才写入
- 凭据脱敏：API Key / Token / 私钥禁止明文写入（插件写入前自动掩码为 `REDACTED`）
